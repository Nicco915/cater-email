# 管理页交互、数据/快照语义与删除矩阵

> 适用范围：本机管理网页与 CLI 的任务回收站、参考资料 CRUD 与机型库导入预览。
> 生产/测试身份判定、文件清理与测试数据清空的安全约束一并说明。

## 1. 任务管理：归档与回收站

### 1.1 列表与筛选
- 默认任务列表只显示“正常”任务；归档与回收站各自有专门入口与计数。
- 支持按状态/类型/搜索筛选与分页。
- 单条与多选批量操作均支持：归档、取消归档、删除到回收站、从回收站恢复。

### 1.2 归档 vs 删除
| 操作 | 列表可见 | 处理/发信行为 | 可恢复 |
|---|---|---|---|
| 归档 | 隐藏（归档视图可见） | **不变**：仍可被处理、重试、重新处理、发信；归档仅隐藏 | 取消归档即恢复 |
| 删除到回收站 | 隐藏（回收站可见） | **暂停**该任务未来的处理、自动重试、补件、邮件指令（重试/重新处理）、待发发送；待发 outbox 取消（记录保留） | 从回收站恢复 |

### 1.3 删除的边界（重要）
- 处理中（PROCESSING）、校验中（VALIDATING）、发送结果不确定（SEND_UNKNOWN），或存在**任意** `sending`/`send_unknown` outbox 行（即使任务状态本身是 READY_TO_SEND）的任务**禁止直接删除**；页面给出“等待处理结束/先核对发送结果”指引，不静默强杀线程。
- 删除检查与写入在**同一个 `BEGIN IMMEDIATE` 事务内**重新读取并判定（消除 TOCTOU）；`outbox.mark_sending` 在认领发送时于同一事务内再次拒绝已删除任务，`list_due` 取到任务后即使被删除也不会发送。批量删除先在同一事务内重检全部项，任一不允许则整体回滚（`BatchDisallowedError`）。
- 删除**已完成**任务不撤回已发邮件；后续同票重复提交仍识别为已处理（去重不失效），需要原有显式确认才能重交付。
- 待发 outbox 取消必须保留记录；**恢复任务不自动重发或重算**，也不自动释放旧取消邮件；原来 pending/失败的补件数据不丢失。
- 恢复 `RETRY_PENDING` 任务后会置“自动重试挂起”（`auto_retry_hold`），`due_for_retry` 不再自动选中；只有显式“重试处理”才清除挂起并继续，原状态历史保留。
- 批量归档/取消归档/删除/恢复均为**整批单事务**：任一不允许项或任一写入失败都回滚全部，不部分删除（已用故障注入测试验证）。
- 重新处理/重试/补件/邮件命令/后台恢复/发件轮询均尊重回收站状态，不只是列表隐藏。
- 回收站任务的“查询状态”邮件回复只说明已删除可联系维护恢复，不泄露其他任务或原业务状态。

### 1.4 永久清理任务文件（仅已删除的终态任务）
- 生产**不提供**从 SQL 硬删任务的按钮。
- “永久清理任务文件”仅对**已删除到回收站且到达终态**（COMPLETED/CANCELLED/FAILED/WAITING_INPUT/READY_TO_SEND）的任务可用。
- 流程：先预览范围 → 勾选确认 → 执行。排除发送结果不确定（SEND_UNKNOWN）的任务。
- 路径限制：只清理 `runtime/tasks/<task_id>/` 下的文件；**保留**任务记录、去重指纹（content_hash/business_identity）、outbox 发送摘要、task_events 审计与 field_provenance。
- 文件清理后**不可恢复原始附件**；页面明确告知。不得顺手删除被其他版本/任务引用的原邮件（原邮件不在本操作范围）。

## 2. 测试数据清空（仅测试身份）
- **不能只凭当前 mode=test 就允许清掉生产库**（用户可切 mode）。身份判定结合持久化身份、当前模式、是否曾用于生产与运行目录绑定，**不只 mode**。
- 身份标记 `runtime_meta.environment` 仅在首次记录时写入，之后不降级：
  - 有效模式为 production → 记 `production` 并永久置 `seen_production`（此后即使切回 test 也不可清空）。该标记在设置更新事务内持久化（`SettingsService.update` 切到 production 时同事务写入），运行中 test→production→test 不重启也无法绕过；清空入口发现当前处于 production 也会实时补记。
  - 模式为 test 且库中**已存在任务/邮件**（例如旧生产库升级）→ 记 `unknown`（不可清空）；
  - 仅“空库 + test 模式”才记 `test`。
  - 同时记录并校验 `environment_runtime_dir`（初始化时的规范运行目录），数据库被复制到其他目录不可清空。
- 若无法可靠判定测试身份（identity 非 test、曾 production、目录不符），**拒绝而非猜目录**；对不明/生产目录隐藏入口且服务端拒绝。
- 清空阻断条件：身份不符、进行中/待重试任务、任意 `sending`/`send_unknown` outbox（含无任务邮件）、邮箱轮询仍在运行。均会拒绝并说明原因。
- 流程：显式二次确认 → 先备份 → **先删文件（失败即中止、数据库不改动）** → 再删数据库任务数据。
- 先删文件再删库：任何文件删除失败都会中止并报错，不会“删了库却忽略文件失败却报告成功”。
- 原始邮件按 `runtime/mail/YYYY/MM/` 年月子目录保存，清理时**递归删除实际原邮件**，不只删根目录文件。
- **保留**：参考资料（国家/别名/机型/机型别名）、config_versions 审计、runtime_meta 身份、backups/diagnostics/schema_migrations。
- 不触碰其他 runtime。
- 清空游标后，下次扫描将重新建立首轮水位（首轮水位变化会在页面说明）；**不改历史补扫策略**。

## 3. 参考资料 CRUD

### 3.1 国家
- 稳定主键为 **alpha3（三位大写字母）**；支持中文/英文名编辑，**不直接改国家码**。
- 需要更换国家码时：新建正确码后迁移关联别名。
- 单条新增/查看/修改/启用/停用；复选框批量停用/恢复；搜索与**真实分页**（50/页，页码为实际切片链接）。
- 停用国家 → 国家自身及其**全部别名对新任务失效**（app 与 core 均不再命中）。
- “删除”默认停用；只有可靠确认未被引用（无有效别名、无机型 scope 引用）才允许物理删除并展示影响与确认。

### 3.2 国家别名
- 新增/查看/改名（重新规范化）/启用/停用/删除；复选框批量启用/停用。
- 别名唯一，**跨国家冲突拒绝**（旧映射不静默覆盖）。
- 别名可删除；若历史快照使用过，审计/历史保留，不破坏快照。
- **父项启停不改写子别名意图**：停用/启用国家只影响匹配（要求 `country.enabled AND alias.enabled`），不会把单独停用的别名一并复活。

### 3.3 机型
- 按 **(规范化机型, 目的国范围)** 独立记录；同机型不同 scope 可共存。
- 保留 915F default 110KW / BRA 123KW 及特殊确认标记；**不得推广未确认规则**（如 SEM919BRZ 保持未确认，匹配时暂停）。
- 单条新增/查看/修改/启用/停用；批量停用/恢复；搜索与**真实分页**（50/页）。
- **网页编辑**：机型列表“编辑”进入独立 GET/POST 编辑页，回填旧值，可改英文品名/商品编码/商品名称/申报要素/特殊标记/核验备注/备注与特殊确认标记，保存写审计；**规范化机型 + 目的国 scope 为稳定键，不在编辑中静默修改**（需要换键请新增记录后停用旧记录）。无需依赖重新 Excel 导入来改单条。
- 停用机型/具体 scope → 别名不能绕回，**特殊 scope 停用不静默 fallback 到 default**。
- “删除”默认停用；有别名引用时拒绝物理删除。

### 3.4 每次变更均审计
保存前后值、操作者、时间、原因（config_versions）。数据校验：空值/长度/编码格式/重复 alias 跨国家/同 scope 冲突；批量先全量校验再事务提交。

## 4. 数据/快照语义（权威模式）
- SQLite 参考资料为**权威来源**。`ensure_seeded` 仅在首次初始化播种一次并记录标记；**删除/停用不可重启后重生**，也不被 core 内置国家表绕过。
- 种子为**完整已支持国家集合**：合并 core 的 ISO 表（含 alpha2，如 CN/FR/US/TG）与 app 额外别名，确保权威模式下 CHN/CN、TGO/TG 等都可解析（旧 app-only 列表曾缺 CHN/TGO/alpha2，导致真实配件样例 UNKNOWN_COUNTRY）。
- **版本化一次性补齐**：`SEED_VERSION` 提升时，老库只补“缺失”的国家/别名，绝不覆盖已有名称/别名、绝不重新启用已停用国家；`reference_tombstones` 记录用户**物理删除**的国家/别名，补齐时跳过，永不复生。删除/改名会写入 tombstone。
- core 离线兼容保留默认内置国家表；但 app 发入快照时**显式标明 `authoritative: true`**，core 据此不使用内置 fallback。
- 新增/停用资料影响**新任务**，**不改历史任务的 references.json 快照**。
- 同版本技术重试用原快照（即使该国家随后被停用仍可重试成功）；显式新版本重处理用最新参考资料。该区别在管理页面写明。

## 5. Excel 机型库导入预览
- 上传 → 预览（新增/未变化/修改/停用影响）→ 确认后写入；**取消不更改资料**。
- 预览为零写入；预览令牌受控、短时有效；上传文件受控，不接受任意路径导入。
- 预览后参考资料已变化时，确认被拒绝并要求重新预览（**防 TOCTOU 覆盖**）。
- 同批导入同 scope 矛盾**整体拒绝**。
- 事务写入、审计、source 行、special 元数据均保留；**重新导入不默认复活停用资料**。
- CLI `import-machines` 兼容初始化用途（直接导入）；`--preview` / `--confirm <token>` 提供预览/确认选项避免无意覆盖。

## 6. 删除矩阵（速查）
| 对象 | 默认删除 | 物理删除条件 | 历史保留 |
|---|---|---|---|
| 任务（回收站） | 暂停+隐藏，可恢复 | 终态+已删除时可清理文件 | 任务记录/去重/发送摘要/审计保留 |
| 国家 | 停用 | 无别名、无机型 scope 引用 | 历史任务快照不变 |
| 国家别名 | 删除 | — | 历史快照使用过则审计保留 |
| 机型(scope) | 停用 | 无别名引用 | 历史任务快照不变 |

## 7. 网页安全与表单结构
- 仅绑定本机回环地址；所有写请求校验同源 Origin + CSRF 令牌；批量 ID 与导入 token 不可越权/任意文件路径。
- CSP 仅允许 `style-src 'self'`、`script-src 'self'`（本地 app.js 仅做全选），不允许 `unsafe-inline`。
- **表单不嵌套**：批量表单与行内操作表单为彼此独立的 form；表格内勾选框通过 HTML5 `form="batch-*"` 关联到对应批量表单，行内按钮各自属于本行表单（各自带 CSRF）。浏览器不会吞并或提前关闭表单；回归测试用 HTML 解析器校验无嵌套 form 且 form 归属正确。
- 全选脚本覆盖 `task_ids / country_alpha3 / machine_key / country_alias_key / machine_alias_key`，按真实 form 归属（`input.form === 表单`）勾选。
- 网页用中文业务表达，不显示 SQL 栈；异常仅给出安全摘要，详情落运行日志。

## 8. 数据库版本与已知限制
- 最新 schema 版本为 **10**（migration 8 生命周期/权威/导入预览；migration 9 `auto_retry_hold`；migration 10 `reference_tombstones`）。迁移为追加式，旧非空库升级保留 tasks/outbox（含发送不确定记录）与既有参考资料。
- **权威种子**：`SEED_VERSION=2`，老库升级只补缺失国家/别名并写 tombstone；停用国家不因重启或补种复活；core 不再 fallback 内置表。
- **身份保护**：`runtime_meta.environment`（test/production/unknown）+`seen_production` 永久标记+`environment_runtime_dir` 目录绑定共同决定清空资格；曾用于生产或身份不明的库不可清空。
- **已知清空限制**：清空仅限“身份为 test 且从未 production”的运行目录；它会清空该 runtime 的任务/邮件/游标（首轮水位重建），先备份，文件删除失败即中止且不改数据库。它不会、也不能清理其他 runtime 或生产数据。
- **未在 Windows 实测**：本轮全部测试在 macOS 以临时库/假 SMTP/模拟网关完成；`tests/app/test_scripts.py` 的 PowerShell 测试因本机无 pwsh 跳过。真实 Windows 收发、凭证、计划任务与初始化脚本仍需在目标 Windows 机器验收，不以 macOS 结果替代。
