# 生产初始化与邮件重新处理

更新日期：2026-11-04。

## 生产初始化

双击根目录 `initialize-production.bat`，会自动创建缺少的生产配置，初始化 `runtime/production` 数据库，并从database目录选取机型Excel或弹出选择窗口导入Sheet1。与测试初始化独立，不复制测试库，不删除已有任务，也不自动开启发信；已有配置和发信设置不会被重置。运行前停止生产处理程序，完成后核对生产白名单和有效开关，再运行 `start-production.bat`。

若缺Python虚拟环境，会先调用安装器，安装器的初始化同样显式指向生产目录。缺.env时仅复制无真实凭证的样例，需要用户填写。初始化/失败窗口保留，显示退出码。

## 重复邮件的区别

- 同一封邮件被轮询重复拉取（同UID、原文或Message-ID重复）：不创建新业务任务，不反复发送提示，避免邮件循环。
- 新来信与已有任务的业务内容相同：发送已处理提示，关联本次任务编号；不再次交付业务文件。
- 新来信为同票但内容变化：暂停并发送确认问题，不自动覆盖。
- 上述提示/追问只有在当前环境已显式允许真实发信时才实际发送；dry-run仅记录发件箱。

## 直接用邮件确认

原任务发起人直接回复程序最新提示邮件，保留主题及回复关系，新增正文单独写：

```text
确认重新处理
```

也接受独立一行 `重新处理`。程序会使用关联任务保存的资料、执行完整校验、生成新版本，再按当前发送设置回复。不需要登录生产电脑操作；缺失或冲突仍会暂停，不因确认而跳过校验。旧版本保留。

确认命令不与目的国、字段修正或新附件混用，避免部分指令被忽略；需要修改资料时先按问题提示补充，再回复最新通知确认。只认可新增正文，不执行引用历史中的旧命令；仅原发起人且仍在当前白名单内有效。请回复最新版本通知，旧版确认、重复确认、处理中、已取消或发送结果未确认的任务不会自动重新交付。此类情况可在管理页核查。

管理页和CLI重新处理入口继续可用。`SEND_UNKNOWN`必须先核对已发送邮件、确认发送结果，不能用回复命令绕过，以免重复发送。
