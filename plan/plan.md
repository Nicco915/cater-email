# 邮件驱动的出口文档转换系统实施计划

> 版本：v1.0 开发执行计划。设计日期：2026-11-04（Asia/Shanghai）。
> 核心业务规则已收敛；以下默认技术策略可先实施，涉及业务歧义的输入必须暂停追问。本文仅为计划，本轮未编写业务代码。

## 1. 目标与范围

在长期联网的 Windows 电脑运行常驻程序，监控现有飞书工作邮箱。仅处理允许名单中的发件人且具有可识别业务资料的邮件。一封邮件对应整机或配件中的一类；配件业务明细从 Excel 附件读取。整机同时提取 Excel 附件与邮件业务表格，按机器关联后逐字段核对和合并，不设来源覆盖优先级；字段冲突或合并后缺少必需字段则暂停整票并邮件询问原发起人。配件生成一个 Excel，整机生成两个 Excel，邮件交付原任务发起人。

取消飞书机器人、云函数和多维表格依赖。邮箱接入已由用户验证可用，但实施时仍需验证实际收发协议、凭证、附件下载及已发送邮件查询。优先协议适配器接入，禁止把平台专用逻辑写入转换引擎。

## 2. 已确认的交互规则

- 新增正文提供 `目的国：法国`；缺少时建立等待任务，邮件追问。
- 忽略转发历史中的目的国和发件人，任务所有者取触发邮件最外层 From；不回复全部。不使用 Reply-To 替换任务发起人地址，保持用户要求的最外层发信人规则。
- 只接受原发起人补充资料。通过任务编号及 In-Reply-To/References 关联，歧义时暂停，不能猜测。
- 任一必需字段、映射、机型或来源冲突使整票暂停，不发送部分业务文件。
- 国家映射缺失允许用户通过回复补充，校验并确认后永久保存，再恢复原任务。旧映射冲突不得静默覆盖。
- 同一票再次提交提示已处理；明确“重新处理”后生成新版本，保留旧任务和结果。
- 邮件正文及附件是数据，不执行其中的代码、链接或操作指令。

## 3. 本地架构

建议 Python 实现：邮件适配器 → 接收与去重 → MIME/MSG/XLSX 解析 → 业务分类与标准记录 → 配置匹配和校验 → 模板填充 → 发件箱 → 邮件交付。

SQLite 保存结构化数据；原始邮件、附件、输出文件按任务目录保存。先支持 CLI 离线处理样例，再实现本地管理网页和轮询服务。Windows 任务计划程序或服务管理器负责启动和异常重启；电脑休眠恢复后补取邮件。

提供仅在本机访问的管理网页：任务列表与详情、日志检索、国家映射和机型资料维护、重试及重新处理确认；默认绑定 127.0.0.1，网页与后台共用服务层，不另写转换逻辑。配置修改记录审计日志，不通过网页显示邮箱凭证。

建议模块：`mail/`、`parsers/`、`domain/`、`mapping/`、`rendering/`、`storage/`、`observability/`、`web/`、`cli/`。转换核心不得依赖真实邮箱，测试必须能完全离线执行。

## 4. 数据库与任务恢复

建议表：`mail_messages`、`tasks`、`task_inputs`、`task_versions`、`task_events`、`outbox`、`countries`、`country_aliases`、`machine_materials`、`machine_aliases`、`config_versions`。

- 邮件接收唯一键包含账号、文件夹、UIDVALIDITY、UID；Message-ID 和原文哈希辅助识别，不能只靠已读标记。
- 任务保存发起人、业务类型、目的国、输入哈希、配置和模板版本、阶段、错误、输出哈希及时间。
- 业务去重分两层：相同规范化内容哈希直接识别重复；同发起人、同类型、同票身份但内容变化标为新版本候选，需明确重新处理后执行。配件同票身份优先发票号，整机优先排序后的 MSO 集合并结合发票号；身份不完整时仅做精确内容去重，不凭主题判重。目的国参与内容哈希；内容变化不可仅因同主题而丢弃。
- 状态：RECEIVED → VALIDATING → PROCESSING → READY_TO_SEND → COMPLETED；补资料进入 WAITING_INPUT，技术错误进入 RETRY_PENDING 或 FAILED。
- 状态变更与 outbox 写入使用事务；单实例运行且以任务锁防止重复处理。
- 邮件发送不承诺严格 exactly-once：先持久化发送意图和确定的 Message-ID，再发送；连接中断导致结果不确定时进入 SEND_UNKNOWN，核对已发送邮件，无法判定则人工处理，不盲目重发。
- 不依赖进程内会话；重启可恢复等待、重试和待发送任务。

## 5. 字段规则

### 配件：一对一

输入优先含补充资料的 `CI-For Dealer (2)`，不能只根据名字选表。结合明细表头、K 列之后补充字段、有效料号行和价格信息识别；多个合格候选有冲突时暂停。`CI-For Dealer` 原表不能自动替代最终调整表。

已确认映射：商品料号←B、申报数量←H、申报单价←最终表 I、净重←L、原产国←E 经过可配置三位码映射、商品编码←M（与 D 冲突时以 M 为准）、商品名称←N、规格型号←O。币制固定 USD；最终目的国取本次用户输入并映射为三位码。输入起止行按表头与料号识别，跳过费用及合计行，禁止硬编码 19～33。

核查发现原表同样有 K～O 补充信息，且 P～S 比最终表更多，因此不能用“列数更多”选表。已确认 `(2)` 名称优先并校验关键字段完整性；找不到最终表或无法唯一选定时暂停并追问。最终表 I 的 15 个单价均与输出一致。

样例毛重 317 来自 Packing List!J23，件数 2 来自 G23，发票号来自最终发票表 E10；已确认三个输出值仅首条填写。样例输出订单号 Z16 的 CBS20250423-219355A 在输入中不存在；用户决定暂时忽略，该字段本期留空、不阻塞任务，禁止复制旧值。位置仅用于审计样例，不得硬编码为解析位置。

已确认规格型号仅将开头 `1||不适合进口报关` 改为 `1|不适合进口报关`，其他连续竖线保持不变。申报总价留空，仅填写单价；其他未使用列保持空白。配件净重读取最终工作表 L 列已有总净重，核对 H 数量×K 单件重量，不除以数量；缺值或公式缓存缺失按异常规则处理。

### 整机：一对二

整机同时解析 Excel 附件与邮件业务表格，不因某一来源字段齐全而跳过另一来源。所需字段包括经销商代码、Dealer Order、Cust. Purch. Order (MSO#)、Order、Material、Serial Number、Total Sales Price。每个来源仅要求提供其实际包含的业务信息，不要求两份资料各自包含全部字段。

用 MSO 优先关联邮件行和箱单机器；可用序列号辅助核对，禁止凭行号或仅凭机型拼接。保存原始值、规范化值和来源定位。逐字段核对：仅一处有值时取该值；两处都有且语义一致时合并并保留双来源；不同则列出两处原值与位置，进入 WAITING_INPUT，询问原发起人，不静默覆盖。合并后仍缺少必需字段，同样列出字段及对应机器后追问。正常的来源互补不属于缺失，不要求重复提供。

比较前仅执行已确认的规范化（如 SO 前导零、机型显式别名），不得用模糊匹配或金额近似掩盖差异。发票单价与 Total Sales Price 是不同业务字段，不能互相覆盖或直接当作同字段冲突；样例两者不同。邮件往来包含多版业务表时需明确版本及对应关系，无法确定则询问。补充邮件仅更新明确提供的字段，不清除已确认数据。

企业物料：商品料号←MSO；机型←输入 Material 标准化匹配；商品编码/商品名称/申报要素/英文商品名称←本地机型库。机型库仅从 `database/整机HS CODE Review 2026-03.xlsx` 的 Sheet1 初始化，不读取 Sheet2；后续本地数据库为维护来源。

固定字段：申报计量单位=台、货品类型=成品、企业计量单位=台、法定比例=1、币制=USD、原产国=CHN。

第二比例=单颗料净重=箱单对应组净重÷数量。新增样例 Packing list：SEM512 24400÷2=12200；SEM520 40000÷2=20000。优先按箱单组中的 MSO 清单关联机器，数量与明细台数必须一致；同机型多组且无法关联时暂停。数据库申报要素原样提取，不因箱单重量而自动改写。

沟通表已确认映射（同时提取 Excel 和邮件表格，核对后合并）：Dealer Code←经销商代码；Dealer Order←同名字段；MSO 与 Material←MSO；Model←输入 Material；Serial Number←同名字段；Machine Price←Total Sales Price；国家←本次用户国家中文名；SO←Order，无前导零加一个，已有则保留，按文本存储。其余字段已确认留空。

## 6. 模板格式保护

从现有 output 工作簿建立专用模板，去掉手工中间工作表和旧业务记录的具体范围须形成清单。保护原始样例，不能直接覆盖。保留目标表的工作表名、表头、说明、字体、颜色、边框、对齐、数字格式、行高、列宽、合并单元格、打印设置和其他原有特性。

只写数据区域；新增行复制已确认的样式原型。标识符按文本写入；金额使用 Decimal，精度和舍入规则须明确。不得盲目压缩申报要素分隔符。读取含公式输入时检查缓存，缺失或过期不能当零；不假设读取库能计算 Excel 公式。

实施前以最小修改验证库的模板往返保真；普通库不能保持某项特性时评估限定范围的 OOXML 修改。选择方案须以样式差异检查和 Excel 实际打开验证为依据。

## 7. 全流程日志与运维

- 结构化 JSONL 运行日志，按日期或大小轮转；SQLite task_events 保存业务状态历史，两者均以 task_id、mail_id、attempt_id 关联。
- 覆盖收信扫描、过滤原因、去重、附件下载及哈希、解析选表、字段来源、映射匹配、校验、等待补充、配置更新、生成、发送、重试、重启恢复及清理阶段。
- 记录阶段耗时、行数、版本、错误码及异常栈；任务详情可追溯每个输出值来自哪封邮件、工作表/行列或配置记录。
- 不记录密码、授权码、令牌及完整邮件正文；详细业务资料留在任务目录，日志仅引用必要标识。
- 提供查看任务、查看错误、重试、确认重新处理、导出诊断包的 CLI。已确认运行日志保留 90 天，原始邮件、附件和输出保留一年，任务状态及配置变更记录长期保存；未完成任务必需资料不自动清理。业务事件日志与任务状态摘要分开管理，避免长期保存完整运行日志。
- 配置变更与数据库备份必须可追溯；凭证保存在 Windows 凭证管理器或等效安全存储，不入 Git、不进入诊断包。
- 忽略自身地址、已知输出、自动回复、退信及 Auto-Submitted 类邮件，设置每任务通知去重，防止邮件循环。

## 8. 技术方案与目录约定

使用 Python、SQLite、服务端本地网页（建议 FastAPI + Jinja2），避免为单人管理页引入独立前端构建。数据库访问集中封装，使用迁移脚本管理结构升级。IMAP/SMTP 为首选候选接入方式，实际以 Windows 机器完成收发验证的通道为准；若使用其他邮箱 API，只替换适配器。依赖版本由执行 agent 在建立环境时验证并锁定，本文不指定未经验证的版本。

Excel 读取/模板填充候选为 openpyxl；以最小往返测试为先决条件。邮件使用标准 MIME 解析，HTML 表格使用结构化解析器，离线 `.msg` 使用专门解析库。不能依赖 Outlook GUI 自动化才能运行。首期无 LLM 依赖，无自动 OCR，不执行 Excel 宏或外部链接。

建议目录：

- `src/cater/`：业务模块，避免在仓库顶层创建可能覆盖标准库的 mail 包。
- `templates/`：三个经清理和验证的版本化模板，不覆盖 output 原始样例。
- `config/`：不含凭证的默认参数、字段别名、允许名单示例。
- `tests/fixtures/`：测试副本及规范化预期结果，原始客户资料不得擅自发布。
- `runtime/`：数据库、任务文件、日志、备份，全部排除出版本控制。
- `plan/`：本计划；`docs/`：字段清单、运行和故障手册。

运行期每任务目录为 `runtime/tasks/<task_id>/v<version>/`，包含 inputs、normalized、outputs；日志记录相对定位。输出先写临时文件，检查通过后原子替换，整机两个输出全部验证通过后才创建交付邮件。

## 9. 模块接口及数据契约

接口名是设计约定，实施可调整命名，但不得跨层混用职责：

| 模块 | 输入 → 输出 | 责任 |
|---|---|---|
| MailGateway | 游标 → 原始邮件；发送意图 → 发送结果 | 拉取、下载、发信和已发送核查，不解析业务 |
| IntakeService | 原始邮件 → 邮件记录/任务关联 | 白名单、自动邮件过滤、去重、任务所有权 |
| SourceParser | 邮件/附件 → SourceRecord 列表 | 解析单元格和表格，保留来源，不写输出 |
| Reconciler | 多来源记录 → 标准记录/问题清单 | 按 MSO 对齐、规范化、缺失和冲突检查 |
| ReferenceService | 国家/机型 → 版本化匹配结果 | 精确匹配和显式别名，不静默模糊匹配 |
| Transformer | 标准记录+配置快照 → 输出行 | 固定值、净重计算、SO 和特定文本清洗 |
| TemplateWriter | 输出行+模板 → 待验收文件 | 仅写白名单数据区域，保留样式 |
| DeliveryService | 验收文件 → outbox/交付状态 | 回复原发起人、追问、发送恢复 |
| AdminService | 管理操作 → 状态/配置变更 | 网页与 CLI 共用，产生审计事件 |

SourceRecord 至少包括字段语义、原值、规范化值、邮件 ID、附件哈希、sheet/单元格或 HTML 表格/行/列。Issue 包括错误码、机器或料号、字段、来源值、所需动作及是否阻塞。所有业务校验完成后一次汇总问题，避免每缺一个字段就发送一封邮件。

同一封中重复引用且内容一致的表格可去重；两份不同版本表格不能取最后一张即认为最新，无法明确选定就询问。同一 MSO 对应多个不同序列号时视为冲突。国家三位码按经确认的映射表转换，不自行混用国家数字代码；内置常见国家基础表，别名允许确认后追加。

机型库导入字段：Sheet1 B→机型、C→英文品名、D→商品编码、E→商品名称、F→申报要素，A/G 保留为参考备注，不直接写入输出。同机型不同已定义目的国范围允许共存；同机型同范围且申报资料不同时导入报错，不能最后一行覆盖。已确认特殊规则（2026-11-04）：915F 目的国为巴西（BRA）时选 Sheet1 特殊列标记“巴西”的 123KW 记录；其他目的国选未标特殊的 110KW 记录。两条均保留，匹配键采用机型+目的国范围，记录此次特殊分支及来源。未定义的其他特殊值仍暂停，不能推广猜测。

匹配保留后缀/特殊配置，不任意删除 SEM 前缀或中文配置说明；需要时建立明确别名。

## 10. 数据库存储细化

| 表 | 关键字段与约束 |
|---|---|
| mail_messages | id、account、folder、uid_validity、uid、message_id、raw_hash、sender、received_at、task_id；协议坐标唯一 |
| mailbox_cursors | account/folder、uid_validity、last_uid、last_scan_at；记录处理水位 |
| tasks / task_versions | task_id、owner、kind、business_key、version、status、destination、content_hash、config_version、template_hash、last_error |
| task_inputs | task/version、mail_id、file_hash、原始文件位置、源类型 |
| task_events | task、attempt、阶段、前后状态、错误码、时间、操作者 |
| field_provenance / task_issues | 字段来源、确认决议、问题状态及补充邮件关联 |
| outbox | purpose、task/version、payload_hash、确定的 message_id、status、attempts；交付/问题摘要去重键唯一 |
| countries / country_aliases | 三位码、中文名、别名规范化值；别名唯一，冲突拒绝 |
| machine_materials / machine_aliases | 标准机型、申报字段、备注、显式别名、版本 |
| config_versions | 变更内容、前版本、操作者、时间；任务固定所用版本快照 |
| schema_migrations | 数据库结构版本与升级记录 |

SQLite 单写入队列、短事务、外键和 WAL；不得在数据库事务内等待邮箱网络请求。文件先落盘且核验哈希，再推进接收游标；中途崩溃允许重复拉取但不能丢邮件。UIDVALIDITY 变化触发重建扫描并用已有指纹去重。备份使用 SQLite 一致性备份机制，不仅复制运行中的主文件。

## 11. 默认运行策略与异常边界

以下为技术默认值，放在配置中，可在部署验收时调整：

- 每 60 秒扫描一次指定文件夹；每轮批量拉取，串行处理业务任务。某票等待补充不阻塞下一票。
- 首次安装不自动处理历史收件箱：设置启用时间水位，提供显式选择历史邮件的离线/管理入口。正常重启按持久化游标补取。
- 发起邮件必须来自允许名单且可识别业务；缺目的国仍建任务追问。非业务邮件记录过滤原因，不回复。已有任务的可信补充邮件不要求重附完整资料。
- 不将“已读/未读”作为处理状态，不删除或移动原邮件；轮询不主动改变用户阅读状态。
- 附件允许 xlsx；邮件正文支持 HTML 表格和可明确分列的纯文本，离线支持 eml/msg。图片/PDF 表格、xls、加密或损坏附件先返回清晰的不支持提示，要求补充 xlsx，不自动猜测。如后续确有此类样例再扩展。
- 附件默认单个最大 25 MB、总计 50 MB，解压和 XML 解析设限；超限明确告知，不重复重试。输出受邮箱实测大小限制控制，超限暂停且保留本地文件，不擅自发送外部分享链接。
- 金额保留来源有效精度，使用 Decimal，不从显示字符串引入千分位歧义；本期不额外分摊配件费用。净重按十进制计算，Excel 二进制尾差在明确精度内比较；涉及真实舍入差异先暂停。整机除法超过模板允许精度时要求确认，不能静默截断。
- 不能可靠判断任意公式缓存是否过期；对数量×重量等可独立验证关系复算核对，无法验证且缓存缺失时要求用户重算保存。首期不自动启动 Excel 执行计算。
- 网络瞬时错误指数退避，建议 30 秒、2 分钟、10 分钟，连续失败转人工可见状态；认证失败直接提示本地管理页，不反复发送邮件。业务错误不进入网络重试循环。
- 同一未变化的问题摘要只发送一次；用户补充产生新问题摘要再通知。等待任务不定时催促，保留到解决或人工取消。
- 网页默认仅本机访问，变更操作使用会话与 CSRF 防护，日志和附件不通过任意路径读取；绑定局域网属于后续范围。
- 每日一致性备份数据库与配置，建议保留最近 30 份；任务数据按既定一年策略处理。备份恢复同时恢复发送记录，恢复后先核对邮箱再允许发送。

## 12. 邮件交互规范

主题统一添加 `[CATER <task_id> v<version>]`，同时保留原主题。发信设置 In-Reply-To/References、Auto-Submitted 标记及自身可识别标识；不能仅凭可伪造的主题标记跳过白名单校验。

追问示例：列出 MSO、缺失字段或冲突双方值及来源，并提供 `MSO=BFWVU；SO=0620186623` 形式的补充示例。目的国示例 `目的国：法国`；映射示例 `国家映射：France=FRA`。结构不明确的自然语言回复再次请求确认，不直接覆盖配置。显式修正输入时保存原值与用户决议，不制造永久未解决冲突。

交付邮件列出任务类型、目的国、明细数和输出附件名；不声称已上传业务系统。管理页提供“仅重新生成”和“重新生成并邮件交付”两个明确动作，后者走发送记录与审计流程。

## 13. 模板交付契约与样例基准

| 输出文件 | 保留工作表 | 表头/数据起始 | 明细数量 |

## 15. 测试与完成标准

采用 pytest 进行核心业务和恢复测试；邮件适配器使用录制/模拟数据，正式外发只在测试发件人和测试收件人下进行。

- 配件：最终表不存在/多候选、不同列数、数据行增减、国家未知、M/D不同、特定前缀清洗且保留其他竖线、公式缺缓存、单价精度。
- 整机：双来源一致/互补/冲突、缺字段、多版本、MSO错配、重复机器、未知机型、同机型多重量组、数量不一致、已有SO前导零。
- 模板：零条有效记录不交付；1行、样例行数及超过样例行数；表头不变、数据行样式继承、旧值不残留、无公式/对象意外丢失。
- 邮件与恢复：重复UID、相同内容新邮件、同票变更、非原发起人补充、无References但有效任务编号、自动回复、退信、进程中断、网络中断、SMTP接受后响应丢失、UIDVALIDITY变化和恢复备份。
- 网页与运维：字段修改审计、映射冲突、输入附件路径约束、诊断脱敏、日志轮转、一年清理不误删等待任务。

完成标准：三份样例输出字段核对通过；所有阻塞问题能通过原发起人回复解决；全流程可按 task_id 查询；重启不丢任务、不无条件重发；Windows 自动运行与备份恢复演练通过；提交配置示例、安装说明、字段清单、故障手册和验收记录。不得只以“文件生成成功”宣告完成。
